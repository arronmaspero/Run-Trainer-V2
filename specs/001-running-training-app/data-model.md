# Data Model: AI-Powered Running Training Web App

This document defines the schema, relationships, and validation rules for the running app.

## Entity Schema

### 1. User
Represents authentication and account state.
*   `id`: UUID (Primary Key)
*   `name`: String (Required)
*   `email`: String (Unique, Required)
*   `password_hash`: String (Required)
*   `created_at`: DateTime
*   `last_login`: DateTime
*   `consent_status`: Boolean (GDPR consent)

### 2. Athlete Profile
Contains running parameters and physiological data.
*   `user_id`: UUID (Foreign Key linking to User, Unique)
*   `date_of_birth`: Date (Optional)
*   `gender`: String (Optional)
*   `resting_heart_rate`: Integer (Optional)
*   `max_heart_rate`: Integer (Optional)
*   `threshold_heart_rate`: Integer (Optional)
*   `vo2_max`: Float (Optional)
*   `weekly_volume_miles`: Float (Required)
*   `runs_per_week`: Integer (Required)
*   `long_run_day`: String (e.g., "Sunday")
*   `unavailable_days`: String (Comma-separated list of days)
*   `injury_notes`: Text (Optional)
*   `strava_client_id`: String (Optional, custom user developer app credentials)
*   `strava_client_secret`: String (Optional, custom user developer app credentials)

### 3. Connected Account
Stores Strava OAuth credentials.
*   `id`: UUID (Primary Key)
*   `user_id`: UUID (Foreign Key linking to User)
*   `provider`: String (Value: "strava")
*   `access_token`: String (Required)
*   `refresh_token`: String (Required)
*   `expires_at`: DateTime (Required)
*   `scopes`: String (Comma-separated scopes)
*   `last_sync_at`: DateTime

### 4. Activity
Represents imported runs from Strava.
*   `id`: UUID (Primary Key)
*   `strava_activity_id`: String (Unique, Nullable if manual)
*   `user_id`: UUID (Foreign Key linking to User)
*   `type`: String (Value: "run")
*   `start_date`: DateTime (Required)
*   `distance_miles`: Float (Required)
*   `moving_time_seconds`: Integer (Required)
*   `elapsed_time_seconds`: Integer (Required)
*   `elevation_gain_feet`: Float (Required)
*   `average_heart_rate`: Integer (Optional)
*   `average_cadence`: Float (Optional)
*   `splits_json`: Text (JSON string containing split list)
*   `gps_polyline`: Text (Encoded polyline string)
*   `matched_session_id`: UUID (Foreign Key linking to Training Session, Nullable)

### 5. Training Plan
A calendar training plan generated by Gemini.
*   `id`: UUID (Primary Key)
*   `user_id`: UUID (Foreign Key linking to User)
*   `race_name`: String (Optional)
*   `race_date`: Date (Optional)
*   `race_distance_miles`: Float (Required)
*   `target_time_seconds`: Integer (Optional)
*   `start_date`: Date (Required)
*   `end_date`: Date (Required)
*   `style`: String (Conservative, Balanced, Ambitious)
*   `status`: String (Active, Completed, Archived)

### 6. Training Session
An individual workout on the plan.
*   `id`: UUID (Primary Key)
*   `plan_id`: UUID (Foreign Key linking to Training Plan)
*   `date`: Date (Required)
*   `type`: String (Easy, Recovery, Intervals, Tempo, Long Run, Strength, Rest)
*   `name`: String (Required)
*   `description`: Text (Required)
*   `duration_minutes`: Integer (Required)
*   `distance_miles`: Float (Optional)
*   `warm_up_json`: Text (JSON structure)
*   `main_set_json`: Text (JSON structure)
*   `cool_down_json`: Text (JSON structure)
*   `target_pace_range`: String (e.g., "7:25-7:40")
*   `target_hr_zone`: String (e.g., "Zone 3")
*   `target_rpe`: Integer (1-10)
*   `garmin_instructions_text`: Text (Workout steps)
*   `status`: String (Planned, Completed, Skipped)

### 7. Plan Change Log
Audit trail of plan modifications.
*   `id`: UUID (Primary Key)
*   `plan_id`: UUID (Foreign Key linking to Training Plan)
*   `user_id`: UUID (Foreign Key linking to User)
*   `change_type`: String (e.g., "drag_and_drop", "ai_rebalance", "injury_mode")
*   `old_value_json`: Text
*   `new_value_json`: Text
*   `reason`: Text
*   `is_ai_generated`: Boolean
*   `is_user_approved`: Boolean
*   `timestamp`: DateTime

## Validation Rules

1.  **Weekly Volume Thresholds**: Onboarding volume increases must not exceed 10% week-over-week in the generated training plans.
2.  **Date Alignment**: Session dates in `Training Session` must lie between the `start_date` and `end_date` of the parent `Training Plan`.
3.  **Authentication**: Password strength must be at least 8 characters, requiring at least one number and one special character.
